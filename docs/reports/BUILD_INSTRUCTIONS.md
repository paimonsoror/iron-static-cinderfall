## 2. The export preset

`export_presets.cfg` holds one preset, `Cinderfall` (ARCH 1.2): Android, runnable, **no Gradle build**, debug APK to
`build/com.normalexception.games.cinderfall.dev.debug.apk`, package `com.normalexception.games.cinderfall.dev`, label
"Cinderfall Dev", version 1 / `0.1.0` (same as `application/config/version`), arm64-v8a + x86_64, min SDK 24 and
target SDK 36 (template defaults), signed with the Godot debug key, immersive mode, `VIBRATE` only (`INTERNET` off).
`export_filter="all_resources"` plus `include_filter="data/*.json, data/strings/*.json"` packs the runtime JSON
(ARCH 5.1); `exclude_filter` keeps `tests/`, `tools/`, `docs/`, `addons/gdUnit4/` and `build/` out.

`command_line/extra_args` stays `""` in the committed file. To bake debug arguments (ARCH 11, for example
`--debug-perf --scenario=hold30`) put them there temporarily, deploy, and revert before committing. Android strips
intent extras sent to the exported launcher, so this is the only way to pass arguments to a device build.

## 3. Commands (PowerShell 5.1; from Git Bash call them as shown; use your checkout root)

```
# 1. Emulator (about 10 s from a quickboot snapshot, 50-100 s cold). Wait 25 s after a COLD boot before launching apps.
powershell -NoProfile -ExecutionPolicy Bypass -File C:\dev\tower-two\tools\run_emulator.ps1
#    options: -ColdBoot  -Gpu host|swangle_indirect|angle_indirect|swiftshader_indirect  -EmuLog <file>  -PublicDns

# 2. Export, install, launch, print the Godot log. Ends with "== RUNNING (pid n)" (exit 0) or "== NOT RUNNING" (exit 1).
powershell -NoProfile -ExecutionPolicy Bypass -File C:\dev\tower-two\tools\deploy_android.ps1 -ProjectPath C:\dev\tower-two -Package com.normalexception.games.cinderfall.dev -Preset Cinderfall -LogSeconds 40

# 3. Smoke test (process, log, renderer, screenshot). Prints "SMOKE OK" (exit 0) or "SMOKE FAIL: <reason>" (exit 1).
powershell -NoProfile -ExecutionPolicy Bypass -File C:\dev\tower-two\tools\smoke_android.ps1 -SkipDeploy
#    omit -SkipDeploy to deploy first; -Soak 180 keeps checking; -MinFps 30 needs a --debug-perf build ([PERF] lines)

# 4. The runtime data must be inside the APK (A07): five data files and four string files
py -3.12 -I -c "import zipfile,sys; n=zipfile.ZipFile(sys.argv[1]).namelist(); print([x for x in n if 'data/' in x and x.endswith('.json')])" C:\dev\tower-two\build\com.normalexception.games.cinderfall.dev.debug.apk

# 5. Permissions (A19): expect VIBRATE only, no INTERNET
"%LOCALAPPDATA%\Android\Sdk\build-tools\36.0.0\aapt2.exe" dump permissions C:\dev\tower-two\build\com.normalexception.games.cinderfall.dev.debug.apk

# 6. Screenshot (cmd from C:\, never from a \\wsl$ working directory; from Git Bash use "cmd //c")
cmd /c "cd /d C:\ && adb exec-out screencap -p > C:\dev\tower-two\build\shots\w1h_emulator.png"

# 7. Stop the emulator when done (it uses 2.5 GB RAM and all cores)
adb emu kill
```

`deploy_android.ps1` imports, exports with the real Godot editor settings (not the per-checkout `APPDATA` redirect of
the test tools), refuses to continue when the APK holds no `data/*.json`, installs with `adb install -r`, wakes the
screen, launches through `monkey`, and writes `build\logs\deploy_export.log` and `build\logs\deploy_logcat.txt`. Run it
from a normal drive path (not `\\wsl$`) and never two at once.

`smoke_android.ps1` checks: process alive; no `SCRIPT ERROR`, `FATAL`, `ERROR: Content:`, `Force quitting`,
`E AndroidRuntime`, crash-buffer or ANR entry for this process; log contains `content ok` and `boot ok`; the boot line
`game boot ... renderer=<method>/<driver>` is `mobile/vulkan` (`-ExpectRenderer`) with no OpenGL fallback line;
screenshot is portrait, not blank and has pixels near amber `#F1A34A` or cyan `#39C9DB`; optional `-MinFps` over the
`[PERF]` lines (ARCH 11 format) after a warm-up. `-ImagePath <png>` runs only the screenshot checks (no device).

## 4. Targeting a physical phone

1. Phone: enable Developer options and USB debugging, plug in, accept the RSA prompt. `adb devices` must list it as
   `device`. (Wireless: Developer options, Wireless debugging, `adb pair <ip>:<port>`, `adb connect <ip>:<port>`.)
2. With the emulator also online, adb needs a serial: `adb devices`, then pass `-Serial <id>` to `deploy_android.ps1`
   and `smoke_android.ps1`. Without `-Serial` and with more than one device online, the scripts stop with the list.
3. The package id is the same on both targets; the preset exports arm64-v8a and x86_64, so phones and the emulator use
   the same APK. A phone has a real GPU: take performance numbers (ARCH 13) there, never on the emulator.
4. Physical-device checks (safe areas, background and resume, thermal, 50-enemy benchmark) are **NOT RUN** by W1-H.

## 5. Emulator notes

General behaviour of `tower_phone` on this laptop (4 cores, 15.7 GB), observed 2026-11-11:

- **Boot.** From the quickboot snapshot the emulator is online in about 10 s; a cold boot takes 50 to 100 s and then
  loads the CPU (load average 30+) for 3 to 6 minutes (longer with `-gpu swangle_indirect`). During that time
  SystemUI shows "System UI isn't responding", and a Godot launch is stopped right after `OnResume` (activity
  `STOPPED`, no `godot` log lines) or force-quit. Wait until `adb shell uptime` shows a 1-minute load below 3 before
  launching, then `adb shell input keyevent KEYCODE_WAKEUP` and `adb shell wm dismiss-keyguard`
  (`deploy_android.ps1` does both). Other Godot processes on the host (parallel agents, `check.ps1`) slow the emulator
  as well and can trigger the same dialog; tap "Wait".
- **Switching `-gpu`.** `adb emu kill`, wait until `emulator.exe` is gone, then `run_emulator.ps1 -Gpu <mode> -ColdBoot`.
  The AVD config keeps `hw.gpu.mode=host`; the command-line flag wins. `-EmuLog <file>` keeps the emulator's own stdout
  (it lists the GPU and Vulkan device it selected; it also contains local IP addresses, so do not commit it whole).
- **Screenshots.** `adb exec-out screencap -p` must run from `C:\` (UNC working directories fail). A black PNG of exactly
  15,580 bytes is the empty 1080x2400 frame; a real frame is tens of kilobytes. The AVD also has a second virtual
  display ("Emulator 2D Display"); the main display is `0`.
- **Immersive mode.** The first launch on a fresh AVD may show the one-time "Viewing full screen" dialog; tap "Got it".
- `adb emu kill` when you are done; the emulator holds 2.5 GB of RAM and three cores.

### 5.1 W1-H result: Mobile/Vulkan does not present on the emulator (BLOCKER for the coordinator)

What works (all verified on the emulator, host GPU, clean preset): export succeeds (54.6 MB APK, 9 data files inside),
install succeeds, the app starts, `content ok` and `boot ok` are logged, and the boot line reports the intended renderer:

```
Vulkan 1.3.0 - Forward Mobile - Using Device #0: Intel - Intel(R) Iris(R) Plus Graphics
[Content] content ok enemies=4 waves=5 hash=09244f72d864
[Game] game boot version=0.1.0 renderer=mobile/vulkan
[Game] boot ok
```

There is no OpenGL fallback (`renderer=mobile/vulkan`, no `OpenGL API` line). What does not work: nothing reaches the
screen. Godot logs `ERROR: Couldn't present to Vulkan queue (VkResult error 5).` at the first presented frame
(drivers/vulkan/rendering_device_driver_vulkan.cpp:3359; that frame is the engine boot splash, before `content ok`, so
project content is not the cause) and twice more around `boot ok`. After that the process sits at 0 % CPU and the
screenshot is a fully black 1080x2400 frame. SurfaceFlinger lists only the black "Background for SurfaceView" layer:
the Vulkan surface never receives a buffer.

| Run | Emulator `-gpu` | Vulkan device Godot used | Result |
|---|---|---|---|
| 1 (acceptance) | `host` (gfxstream to the Intel Iris Plus Vulkan 1.3 driver) | Intel Iris Plus Graphics, Vulkan 1.3.0 | present error, black screen. `android_w1h/host_gpu_*`, `w1h_emulator_black_screenshot.png`, `acceptance_commands_output.txt` |
| 2 | `swangle_indirect` (gfxstream to SwiftShader) | SwiftShader Device (LLVM 10.0.0), Vulkan 1.2.0 | identical present error, black screen. `android_w1h/swangle_gpu_*` |
| 3 (experiment, reverted) | `host`, preset `command_line/extra_args="--disable-vsync"` | Intel Iris Plus | "requested V-Sync mode Disabled is not available" (only FIFO is offered), same present error. `android_w1h/experiment_disable_vsync_godot_log.txt` |

Not tried: `angle_indirect` and `swiftshader_indirect` (the brief names host and swangle_indirect only), and any
OpenGL run, because the owner decision forbids it and `project.godot` is not W1-H's. The same code renders correctly
on the desktop through the same Mobile/Vulkan renderer (`android_w1h/desktop_reference_view_sandbox_1080x2400.png`,
made with `capture.ps1`, `renderer=mobile/vulkan`), so the failure is in the emulator's guest Vulkan swapchain with this
Godot build, not in the scene.

Options for the owner, none taken by W1-H: (a) validate Vulkan on a physical phone (not available here, **NOT RUN**) and
treat the emulator as unsupported for 3D until a newer emulator or system image presents; (b) accept an emulator-only
OpenGL build for smoke runs (`command_line/extra_args="--rendering-method gl_compatibility --rendering-driver opengl3"`
in a local, uncommitted preset change), knowing that `smoke_android.ps1` then fails on purpose (`-ExpectRenderer
gl_compatibility/opengl3` lets it pass for that diagnostic build); (c) revisit D1. Until then `smoke_android.ps1`
fails with `SMOKE FAIL: Vulkan errors in the log` on every emulator run. The APK manifest declares
`android.hardware.vulkan.level` and `.version` as `required=false` (Godot's default for the Mobile renderer), so
devices without Vulkan 1.0 still install and use `fallback_to_opengl3`.
